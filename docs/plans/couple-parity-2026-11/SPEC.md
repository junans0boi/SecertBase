# Spec: 커플 앱 대체 가능성 확보 (2026-11)

용어는 `CONTEXT.md`를 따른다. 작성: 커플 마스터 세션(자체 grilling 기반). 관련: `docs/product/2026_COUPLE_APP_RETENTION_RESEARCH.md`, `docs/product/RESEARCH_2026-10_LAUNCH_READINESS.md`, 하드닝 스펙 #202.

## 목표

Between·SumOne류 커플 앱을 **완벽하진 않아도 대체할 수 있는 수준**으로 올린다. 단, 경쟁앱을 베끼지 않는다. 대체 가능하려면 "매일 열 이유"를 경쟁앱 수준으로 갖추되, 그 구현은 Secret Base의 고유한 축(장소·순간·놀이·이해)에 묶는다.

## 저작권·차별화 원칙 (모든 티켓이 지킨다)

1. 보호되지 않는 것: "하루 한 질문", "둘 다 답해야 공개", "채팅", "D-day 위젯", "공유 일정" 같은 **일반 기능 개념**. 따라 해도 된다.
2. 따라 하면 안 되는 것: 경쟁앱의 **UI 레이아웃·화면 구성의 고유한 조합, 문구, 질문 목록, 캐릭터·아이콘·일러스트, 앱 이름과 유사한 명칭, 브랜드 색 조합**. 질문·문구·에셋은 전부 직접 작성하거나 자유 라이선스만 쓴다. 외부 서비스의 콘텐츠를 복사해 넣지 않는다.
3. 고유 색깔 = **"기억이 장소와 놀이로 이어진다"**. 모든 신규 기능은 최소 하나의 기존 자산(지도 핀, MomentLoop, 기념일, 비밀기지 마일스톤, 놀이)과 연결된다. 연결이 없는 기능은 만들지 않는다.
4. 용어는 우리 것을 쓴다. 신규 사용자 표면의 이름은 아래 표를 따른다.

| 일반 기능 | Secret Base 표면 이름 | 고유 장치 |
| --- | --- | --- |
| 하루 한 질문 | **마주 열기** | 둘 다 답하면 봉인이 풀리는 연출, 질문이 우리 지도 장소·기념일을 참조, 놓쳐도 벌점 없이 나중에 답 |
| 채팅 | **쪽지** | 짧은 글 중심, 장소·순간 첨부, 예약 열람(정해둔 시각에 열림), 읽음 표시 |
| 위젯 | **기지 위젯** | D-day와 "오늘 서로 남긴 것" 상태, 비밀기지 레벨 |
| 공유 일정 | **데이트 계획** | 위시 장소에서 시작, 다녀오면 애프터글로우로 닫힘 |
| 초대 | **기지 초대장** | 링크 하나로 앱 열기·설치 안내 |

## 자체 grilling 기록

- **Q. 채팅을 넣어야 대체가 되는가?** 예. Between의 습관은 대화에서 시작한다. 단 풀 메신저(파일·통화·이모티콘 스토어)는 비용이 크다. → "쪽지"로 텍스트·사진·반응·읽음·푸시까지만 하고, 통화·이모티콘 스토어는 하지 않는다.
- **Q. 기존 코드의 `/qa`를 그냥 켜면 되는가?** 아니오. `routes.js`의 `/qa/today`는 `user_id`를 클라이언트가 보내고, 질문이 Couple 범위가 아닌 전역 질문이다. 하드닝 원칙(JWT에서 사용자·Couple 도출)과 충돌한다. → 새 모듈로 다시 만들고 레거시 `/qa`는 게이트로 막은 채 둔다.
- **Q. 질문 목록을 어디서 얻는가?** 경쟁앱 질문을 쓰지 않는다. 카테고리 5개 × 각 40문항 이상을 우리가 직접 쓴다. 장소·기념일 참조형 템플릿 질문을 둔다.
- **Q. 스트릭(연속 일수)을 둘 것인가?** 둔다. 단 끊겨도 벌점이 없고, "놓친 질문"은 나중에 둘이 함께 채울 수 있다. 죄책감 유발 문구를 쓰지 않는다(리서치 문서의 원칙 4).
- **Q. 지금 안 하는 것은?** 결제·프리미엄, iOS, 통화, 이모티콘 스토어, 타사 대화 가져오기(형식 미확인이라 조사 후), Sentry(외부 계정 필요).
- **Q. 개인정보 위험은?** 쪽지 본문은 푸시에 싣지 않는다(기존 알림 원칙). 쪽지·답변은 Couple 범위이며 비활성 Couple에서는 접근 불가. 분리 시 처리는 기존 `couple-separation.js` 정책을 따른다.
- **Q. 순서는?** 파일 충돌이 없는 세 티켓을 먼저(마주 열기, 쪽지, 기지 초대장), 의존성·공통 파일(`pubspec.yaml`, `AndroidManifest.xml`)이 겹치는 것은 이후 물결에서(기지 위젯, 데이트 계획, 알림 확대).

## 완료 기준 (스펙 전체)

- 신규 사용자 둘이 가입→초대장으로 연결→쪽지를 주고받고→마주 열기에 답하고→홈 위젯에서 상태를 본다.
- 모든 신규 서버 경로는 JWT에서 사용자·활성 Couple을 도출하고 클라이언트 `user_id`를 무시·거부한다(`getAuthenticatedActor`).
- 서버 `npm test`, 앱 `flutter analyze` + `flutter test` 통과. 신규 기능마다 서버 통합 테스트와 앱 위젯 테스트를 함께 추가한다.
