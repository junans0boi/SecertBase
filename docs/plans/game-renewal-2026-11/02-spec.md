# 02. Spec — 블랙잭·도둑잡기·제로·해적 룰렛·패널티킥 2.0

> 상태: `needs-approval` (사용자 승인 뒤 `ready-for-agent`)
> 근거 문서: `00-analysis.md`(현황·시뮬레이션), `01-grilling.md`(결정 Q1–Q48, 승인 시 확인할 결정 D1–D7)

## Problem Statement

커플이 **놀이(Play)** 에서 다섯 게임을 하면 다음 일이 생깁니다.

- **블랙잭**은 세 판 중 두 판 가까이(39%)가 무승부로 끝납니다. 설명은 "딜러 교대"인데 딜러가 없고, 상대가 스탠드했는지도 안 보입니다.
- **도둑잡기**는 상대 카드를 뽑아도 무슨 카드인지 알려 주지 않고, 카드를 뺏긴 사람 화면에도 "짝이 맞춰져 버렸습니다"가 뜹니다. 카드 뒷면은 깨진 글자(▯)입니다.
- **제로**는 한 판에 평균 15~25라운드가 걸립니다. 결판 나는 라운드가 17~28%뿐이고, 내 숫자보다 작은 합계 같은 맞힐 수 없는 값도 고를 수 있습니다.
- **해적 룰렛**은 통 그림과 구멍 격자가 따로 놀고 칼 꽂는 연출이 없으며, 벌칙 내용이 없습니다. 방장만 시작할 수 있고 선공은 항상 같은 사람입니다.
- **패널티킥**은 키퍼가 막을 확률이 11%라 사실상 키커 놀이입니다. 인물이 작은 남성 축구 선수로 그려져 있고 소리가 없습니다. 처음 하는 사람은 규칙을 알 길이 없습니다.

다섯 게임 모두 카드·소리·연출이 밋밋하고, "다시 하기"가 상대 동의 없이 새 판을 만들며, 결과 저장에 판 식별자가 없습니다.

## Solution

다섯 게임을 **탱크 대작전 2.0에 준하는 수준으로 새로 만듭니다.** 규칙이 사실상 틀린 세 게임은 규칙을 바꾸고, 나머지 둘은 규칙을 유지한 채 공정성을 보정합니다. 모든 게임은 앱의 파스텔 톤으로 통일하고, 코드로 합성한 효과음과 벡터로 그린 그림을 씁니다.

| 게임 | 핵심 변화 |
|---|---|
| 블랙잭 | 먼저 2승(최대 5라운드)으로 무승부 1% 이하, 업카드 공개·히트 공개로 읽는 재미, 버스트 즉시 종료, 30초 자동 스탠드, 민트 펠트 테이블과 딜·뒤집기 연출 |
| 도둑잡기 | 뽑은 카드 공개 연출, 정렬되는 부채꼴 손패(NEW 표시), 버린 짝 더미, 한 화면 레이아웃, 이모지 리액션 |
| 제로 | 예측 범위를 합리적으로 제한, 5라운드 합산 + 근접 점수로 한 판 5~7라운드, "3 + 2 = 5" 계산 공개, 별도 화면으로 분리 |
| 해적 룰렛 | 구멍이 통 위에 있는 큰 통, 칼 꽂기 연출, 폭탄 확률 게이지와 4단계 표정, 이긴 사람이 정하는 벌칙 카드, 선공 무작위·짝수 구멍 |
| 패널티킥 | 3방향 규칙(선방 33%), 상대 킥 기록으로 읽기, 마스코트 + 프로필 이모지 얼굴, 첫 판 요약 설명, 파스텔 낮 경기장 |
| 공통 | 벡터 카드, 공용 효과음 엔진, 재대결 합의, `gameId` 멱등 저장, 시리즈 전적, 게임별 잠수 안내, 공용 리액션 |

## User Stories

### 공통
1. 사용자로서, 카드 뒷면과 무늬가 어떤 기기·네트워크에서도 같은 모양으로 보이기를 원합니다. 그래야 깨진 글자(▯)를 보지 않습니다.
2. 사용자로서, 이 게임들이 앱의 따뜻한 파스텔 톤으로 보이기를 원합니다. 그래야 로비에서 게임으로 넘어갈 때 화면이 튀지 않습니다.
3. 사용자로서, 카드 넘기는 소리, 칼 꽂는 소리, 골 소리가 나기를 원합니다. 그리고 소리를 끄고 그 설정이 기억되기를 원합니다.
4. 사용자로서, "다시 하기"를 누르면 상대에게 재대결 요청이 가고, 상대가 수락해야 새 판이 시작되기를 원합니다. 그래야 결과를 보던 도중 화면이 바뀌지 않습니다.
5. 사용자로서, 재대결을 거듭해도 "이번 방 전적 3 : 2"가 이어서 보이기를 원합니다.
6. 사용자로서, 같은 판이 두 번 기록되거나 XP가 두 번 들어가지 않기를 원합니다.
7. 사용자로서, 지금 하는 게임과 상관없는 게임의 잠수 안내가 뜨지 않기를 원합니다.
8. 사용자로서, 로비에서 "게임 시작"을 누르면 곧바로 게임이 시작되기를 원합니다. 같은 걸 두 번 누르지 않습니다.
9. 사용자로서, 내 차례, 시간 초과, 결과 같은 순간이 화면 가운데에서 알아보기 쉽게 알려지기를 원합니다.

### 블랙잭
10. 플레이어로서, 설명대로 규칙이 맞기를 원합니다("딜러" 같은 없는 규칙이 없어야 합니다).
11. 플레이어로서, 먼저 2승하면 끝나기를 원합니다. 그래야 무승부로 끝나는 허무함이 없습니다.
12. 플레이어로서, 상대의 업카드와 히트로 받은 카드, 그리고 상대가 스탠드했는지를 보고 싶습니다. 그래야 상대 합을 짐작해 결정할 수 있습니다.
13. 플레이어로서, 상대의 숨은 카드와 블랙잭 여부는 라운드가 끝날 때까지 숨겨지기를 원합니다.
14. 플레이어로서, 버스트하면 바로 그 라운드가 끝나기를 원합니다. 불필요하게 한 번 더 누르게 하지 않습니다.
15. 플레이어로서, 내 카드가 항상 화면 아래, 상대 카드가 위에 오기를 원합니다.
16. 플레이어로서, 현재 라운드 승수(●○)가 화면에 늘 보이기를 원합니다.
17. 플레이어로서, 라운드가 끝나면 숨은 카드가 하나씩 뒤집히는 연출을 보고 싶습니다.
18. 플레이어로서, 다음 라운드는 두 사람이 모두 "준비"해야 시작되기를 원합니다.
19. 플레이어로서, 직전에 진 사람이 다음 라운드의 후공이 되기를 원합니다. 그래야 따라잡을 기회가 있습니다.
20. 플레이어로서, 내 차례에 남은 시간(30초)이 보이고, 시간이 지나면 자동으로 스탠드되기를 원합니다.

### 도둑잡기
21. 플레이어로서, 상대 카드를 뽑으면 그 카드가 크게 뒤집혀 무엇인지 보이고, 짝이면 버려지고 아니면 내 손패에 들어가는 모습을 보고 싶습니다.
22. 플레이어로서, 카드를 뺏기면 "◯◯을 뺏겼어요"처럼 내 어떤 카드가 갔는지 알고 싶습니다.
23. 플레이어로서, 내 손패가 랭크순으로 정렬되어 보이고 새로 들어온 카드가 "NEW"로 표시되기를 원합니다.
24. 플레이어로서, 조커가 내 손에 들어오거나 상대에게 넘어갈 때 눈에 띄는 연출을 보고 싶습니다.
25. 플레이어로서, 상대와 내 손패가 스크롤 없이 한 화면에 들어오기를 원합니다.
26. 플레이어로서, 지금까지 버려진 짝이 몇 쌍인지 보고 싶습니다.
27. 플레이어로서, 이모지로 표정 연기를 할 수 있기를 원합니다("😏 조커 여기 있다").

### 제로
28. 플레이어로서, 합계 예측으로 내 숫자보다 작은 값을 고를 수 없기를 원합니다. 틀릴 수밖에 없는 선택지가 없어야 합니다.
29. 플레이어로서, 한 판이 5~7라운드 안에 끝나기를 원합니다.
30. 플레이어로서, 둘 다 못 맞혔을 때도 더 가까운 쪽이 점수를 얻어 결판이 나기를 원합니다.
31. 플레이어로서, 결과를 "3 + 2 = 5"처럼 계산으로 보고, 누가 왜 점수를 얻었는지 한 줄로 알고 싶습니다.
32. 플레이어로서, 숫자를 크게 탭해서 고르고 예측도 칩으로 한 번에 고르고 싶습니다. `+`를 여러 번 누르지 않습니다.
33. 플레이어로서, 5라운드 뒤 동점이면 한 라운드씩 더 해서 승부가 나기를 원합니다.

### 해적 룰렛
34. 플레이어로서, 칼이 통의 구멍에 꽂히는 것을 보고 싶습니다. 구멍은 통에 붙어 있어야 합니다.
35. 플레이어로서, 남은 구멍 기준 폭탄 확률(%)이 보이고 해적의 표정이 점점 겁먹기를 원합니다.
36. 플레이어로서, 폭탄이 터지면 해적이 하늘로 날아가는 연출을 보고 싶습니다.
37. 플레이어로서, 이긴 사람이 벌칙을 정하고, 진 사람이 그 벌칙 카드를 크게 보기를 원합니다.
38. 플레이어로서, 진 사람이 "했어요!"를 누르면 이긴 사람이 알 수 있기를 원합니다.
39. 플레이어로서, 방장이 아니어도 판을 시작하고 구멍 수 프리셋을 고를 수 있기를 원합니다.
40. 플레이어로서, 누가 먼저 고를지가 매번 무작위이고 구멍이 짝수라서 한 사람만 불리하지 않기를 원합니다.

### 패널티킥
41. 플레이어로서, 키퍼가 막을 수 있는 현실적인 확률(약 1/3)로 판이 진행되기를 원합니다.
42. 플레이어로서, 상대의 지난 킥 방향(최근 5번)을 보고 습관을 읽고 싶습니다.
43. 플레이어로서, 누가 먼저 찰지가 무작위이기를 원합니다.
44. 플레이어로서, 귀여운 캐릭터(내 프로필 이모지가 얼굴)가 밝은 낮 경기장에서 뛰는 것을 보고 싶습니다. 거칠거나 "게임 좀 하는 사람용" 느낌이 아니어야 합니다.
45. 플레이어로서, 방향을 한 번 탭하고 큰 버튼 하나로 확정하고 싶습니다.
46. 플레이어로서, 처음 하면 규칙이 한 화면으로 설명되고, 나중에도 `?`로 다시 볼 수 있기를 원합니다.
47. 플레이어로서, 슛마다 휘슬·킥·그물·환호/탄식 소리와 색종이/"나이스!" 연출을 보고 싶습니다.
48. 플레이어로서, 20초 안에 못 고르면 무작위로 자동 선택되어 판이 끊기지 않기를 원합니다.

## Implementation Decisions

### 공통 · 파일 배치 (클라이언트)
- **`lib/core/game_sfx/`**: 효과음 공용화.
  - `synth_core.dart`: 탱크 합성기의 빌딩 블록(`_tone`, `_noise`, `_note`, `_finish`, WAV 래핑)을 공개 API로 옮깁니다. 파형 합성은 순수 Dart입니다.
  - `game_sfx.dart` + `game_sfx_web.dart` + `game_sfx_stub.dart`: 지금의 `TankSfx`를 일반화한 재생기. `play(SfxRecipe, {volume})`, `muted`, `setMuted`, `init()`(미리 합성). 웹에서만 재생하고 테스트에서는 무음.
  - `recipes/{cards,duel,pirate,soccer,zero,common}.dart`: 소리 레시피. 탱크 레시피는 `tank/`에 남기고 새 합성기를 씁니다.
  - 음소거 키는 `game_sfx_muted` 하나로 합치고, 옛 `tank_sfx_muted`는 처음 한 번 읽어 옮깁니다.
  - 탱크 동작은 **완전히 같아야** 합니다(회귀 테스트).
- **`lib/widgets/play_kit/`**: 공용 부품.
  - `playing_card.dart`: `PlayingCard`(앞면/뒷면/조커, 크기 3종, 하이라이트·NEW 표시 옵션), `SuitPainter`(`Path`로 ♠♥♦♣), `CardBackPainter`(하트 패턴).
  - `game_turn_banner.dart`, `game_result_sheet.dart`, `game_toast.dart`, `confetti_burst.dart`, `reaction_bar.dart`(이모지 6종).
  - 색은 `kMain*` 토큰을 쓰고, 게임이 포인트 색을 인자로 넘깁니다.
- 게임별 화면은 탱크처럼 **폴더로 나눕니다**: `games/blackjack/`, `games/oldmaid/`, `games/zero/`, `games/pirate/`, `games/penalty/`. 기존 `*_screen.dart`는 얇은 진입점으로 남겨 import를 깨지 않습니다.
- `GameScaffold`는 `gameType`을 받아 `GameNoticeListener`에 넘깁니다(잠수 안내 필터).

### 공통 · 서버
- **재시작**: `RESTARTABLE_GAME_TYPES`에 `blackjack`, `oldmaid`, `rps`(제로), `pirate`, `penalty`를 추가하고, 게임별 `restart*Game(roomCode, series)`을 둡니다(탱크의 `restartTankGame`과 같은 틀). 새 판은 `series`를 이어받습니다.
- **판 식별자·정산**: 판마다 `gameId`(`crypto.randomUUID()`)를 상태에 넣고, 종료 때 `recordGameOutcome({ winner, players, gameType, gameId })`만 호출합니다. 해적 룰렛의 `saveGameResult` 직접 호출과 await 없는 XP를 지웁니다.
- **무작위 선공**: 블랙잭 1라운드, 해적 룰렛, 패널티킥 첫 킥커를 서버가 무작위로 정합니다. 엔진 함수는 테스트하기 쉽게 `random` 주입을 받습니다.
- **리액션**: `game:reaction { emoji }` → 허용 목록 6개만 검증, 사용자별 1.5초 쿨다운, 방 전체에 `game:reaction { by, emoji, at }`.
- **잠수 안내**: `game:afk:*` 페이로드의 `gameType`을 클라이언트가 사용합니다(서버 변경 없음).
- 새 이벤트는 `docs/SOCKET_EVENTS.md`에 문서화합니다.

### 블랙잭
**엔진 (`blackjack-engine.js`)**
- 상태: `gameId, status, players, round(1..5), wins{id:n}, firstPlayer, phase, currentTurn, hands, statuses, turnDeadline, timeouts, rounds[], lastRoundResult, ready{id:bool}, result, series`.
- `phase`: `player_turn` → `round_result`(공개 연출 구간) → `finished`.
- 라운드마다 새 덱 52장. 카드 2장을 받고 **0번은 업카드(공개), 1번은 홀카드(비공개)**. 히트 카드는 공개.
- 블랙잭(처음 2장 21)은 일반 21보다 강합니다. 블랙잭 여부는 라운드 종료까지 비공개이고 턴 순서에 노출되지 않게 처리합니다(블랙잭 보유자도 정상 순서에서 `stand` 상태가 됩니다).
- **버스트 즉시 종료**: 버스트하면 그 라운드가 바로 끝나 상대가 이깁니다(두 명 모두 버스트하는 경우는 구조상 없음).
- **선후공**: 1라운드는 `random`으로 결정. 이후 직전 라운드 패배자가 후공(= 상대가 먼저 행동). 무승부 라운드는 선후공을 바꿉니다.
- **종료**: 먼저 2승하면 `finished`. 무승부 라운드는 승수에 더하지 않고 `round`만 증가합니다. 5라운드 뒤 어느 쪽도 2승이 아니면 `winner: 'tie'`.
- **다음 라운드**: `round_result`에서 양쪽이 `next_round`를 눌러 `ready`가 둘 다 true일 때 시작합니다.
- **타이머**: 내 차례 시작 시 `turnDeadline = now + 30s`. 서버 타이머가 만료되면 자동 `stand`, `timeouts[id]` 증가. 3회면 기권(`forfeit`).
- `serializeFor(game, viewerId)`: 내 손은 전체, 상대 손은 `[업카드, …히트 카드 공개, 홀카드는 {hidden:true}]`. 상대 점수는 `visibleScore`(공개 카드 합)만. 상대 `statuses`는 `playing|stand|bust`만 공개(`blackjack`은 `playing`으로 표기, 라운드 종료 시 공개).
- 이벤트: `game:blackjack:updated`(전체 투영)만 사용합니다. 클라이언트는 이전 상태와 비교해 연출합니다.

**화면 (`games/blackjack/`)**
- 위: 상대 아바타 + 카드, 아래: 내 카드. 항상 같은 위치.
- 상단 바: 라운드 승수 ●○ 두 줄, 남은 시간 링.
- 카드 딜은 덱 위치에서 날아오기, 홀카드는 뒤집어 공개, 버스트는 흔들림, 블랙잭은 반짝임.
- 하단: `히트`, `스탠드` 큰 버튼(영문 병기 없음). 상대 차례 땐 "상대가 고르는 중" + 상대 상태 배지("스탠드!").
- 라운드 종료: 숨은 카드가 하나씩 뒤집히고 결과 시트("이번 라운드 승리! 1 : 0")가 나오며 "다음 라운드" 준비 버튼.
- 최종 결과는 `GameResultSheet`(전적, 재대결).
- 로비 설명 문구: "숨은 카드 한 장으로 겨루는 1:1 21점 대결".

### 도둑잡기
**서버**
- 상태에 `gameId`, `series`, `discards[]`(버려진 짝의 랭크, 공개), `log[]`(최근 6개: `{by, paired, rank|null, at}`; 짝이 아닐 때 랭크는 `null`) 추가.
- 뽑기 처리 후 전용 이벤트 **`game:oldmaid:drawn`**을 사용자별로 따로 보냅니다.
  - 뽑은 사람: `{ by, slot, card, paired, pairedRank, jokerMoved, handSize }`
  - 뺏긴 사람: `{ by, slot, card(내가 뺏긴 카드), paired, pairedRank, jokerMoved, handSize }`
  - `card`는 항상 "그 사용자가 이미 아는 카드"입니다. 상대 손패의 실제 id는 어디에도 보내지 않습니다.
- 서버의 손패 섞기·슬롯 별칭은 그대로 유지합니다.
- 결과 저장은 `gameId`와 함께 `recordGameOutcome`.

**화면 (`games/oldmaid/`)**
- 세로 한 화면, 스크롤 없음: 상대 부채꼴(뒷면) → 중앙 구역(버린 짝 더미 "N쌍", 뽑기 연출, 최근 한 줄) → 내 부채꼴 → 리액션 줄.
- 내 손패는 클라이언트에서 랭크순 정렬 + 조커 맨 오른쪽 + 부채꼴 겹침(13장 이상도 한 줄). 새 카드 "NEW"와 빛(다음 행동 때까지).
- 뽑기: 탭한 카드가 위로 올라오고 → 중앙에서 크게 뒤집힘 → 내 손패로 날아가거나 짝이면 "짝!" 이펙트와 함께 더미로. 뺏긴 쪽은 카드가 사라지고 "◯◯을 뺏겼어요" 토스트.
- 조커: 뽑는 순간 어두운 효과음과 카드가 붉게 흔들림, 내 손패의 조커는 계속 붉은 테두리.
- 결과: `GameResultSheet`(조커를 든 사람 패배, 전적, 재대결).
- 상대가 고르는 동안 상대 손이 반짝이는 대신 "뽑는 중..." 배지.
- `ReactionBar`: 이모지 6종, 눌러서 말풍선이 3초 뜸.

### 제로 (`mode: 'hanabagi'` 유지)
**엔진 (`rps-engine.js`)**
- 새 함수 `resolveZeroRound(pick1, pick2)` → `{ total, distance:[d1,d2], exact:[b1,b2], points:[p1,p2], roundWinner }`.
  - 정확히 맞힌 사람 2점(둘 다 맞히면 각 2점). 아무도 못 맞히면 더 가까운 쪽 1점. 같은 거리면 0점.
  - `roundWinner`는 점수가 더 높은 쪽, 같으면 `'draw'`.
- 검증: `fingers` 0~5, `guess`는 **`[fingers, fingers+5]`** 범위. 벗어나면 `invalid_guess`로 거부(화면에 안내).
- 게임 진행: `maxRounds = 5`, 점수 합산. 5라운드 뒤 동점이면 한 라운드씩 서든데스(`suddenDeath: true`), 결판 나면 종료.
- 상태/이벤트: `round_result` 페이로드에 `points`, `distance`, `exact`, `maxRounds`, `suddenDeath`, `gameWinner`를 더합니다. 기존 필드(`total`, `fingers`, `guesses`, `scores`, `history`)는 유지합니다.
- 기존 `resolveHanabagiRound`는 **지우지 않고** 새 함수가 안정되면 정리합니다(다른 호출부 확인 필요).

**화면 (`games/zero/zero_screen.dart` 신설)**
- `rps_screen.dart`에서 제로 관련 코드를 모두 옮겨 가위바위보 화면을 가볍게 합니다.
- 입력: 손 카드 6장(0~5)을 한 줄에 크게, 아래에 "예측"으로 가능한 합계 칩(내 숫자 ~ +5). 선택한 손은 커지고 흔들림. 큰 "제출!" 버튼.
- 대기: 내가 고른 값을 요약해 보여 줌("내 손 3 · 예측 5").
- 공개: "하나~둘~셋!" 카운트에 맞춰 두 손이 가운데로 올라오고 "3 + 2 = 5" 계산 → 판정 한 줄 → 점수 진행 막대(5칸) 채움.
- 판정 문구는 정확 적중 / 근접 승 / 같은 거리를 구분합니다.
- 서든데스 라운드에는 "마지막 한 판!" 배지.

### 해적 룰렛
**서버**
- `start`: `{ slots: 6|8|10|12 }`(스키마를 짝수 프리셋으로 제한). 누구든 시작 가능. 선공은 `random`.
- 상태: `gameId, slots, bombSlot, pickedSlots, players, currentTurn, phase('playing'|'exploded'), series, penalty{text,by,doneAt}`.
- `pick`: 폭탄이면 상태를 **삭제하지 않고** `phase: 'exploded'`로 바꾸고 결과를 기록합니다(`recordGameOutcome`). 이벤트 `game:pirate:exploded { loser, winner, bombSlot, gameId }`.
- `slot_picked`에 `remaining`, `riskPct`(= 100 / 남은 구멍, 반올림)를 더합니다.
- **벌칙**: `game:pirate:penalty { text }`(이긴 사람만, 한 번, 1~30자, 앞뒤 공백 제거) → 방에 `game:pirate:penalty { by, text }`. 진 사람은 `game:pirate:penalty_done`을 보낼 수 있고 방에 `{ by }`로 중계.
- `reset`/재시작은 재시작 프로토콜로 대체. 복원(`session:restore`)은 `exploded` 단계도 되살립니다(벌칙 단계 포함).

**화면 (`games/pirate/`)**
- 통 하나를 크게 그립니다(원기둥 앞면). 구멍은 통 몸통 위에 가로 2~3줄로 배치하고 번호는 작게.
- 칼 꽂기: 위에서 떨어져 구멍에 꽂히고 통이 흔들림 + 칼 꽂는 소리. 이미 꽂힌 구멍은 칼이 보입니다.
- 폭탄 확률 게이지(%)와 해적 표정 4단계(여유 → 걱정 → 땀 → 비명). 확률 30%↑에서 통 떨림.
- 폭발: 뚜껑이 열리고 해적이 하늘로 날아감(별·파편), "펑!" 소리, 진 사람 화면에 붉은 번쩍임 약하게.
- 벌칙 단계: 이긴 사람은 프리셋 칩 10개 + 직접 입력(30자), 진 사람은 "◯◯이(가) 벌칙을 고르는 중…". 정해지면 큰 벌칙 카드가 열리고 "했어요!" 버튼.
- 시작 전 화면: 구멍 수 프리셋 세 개(빠른 6 / 보통 8 / 길게 12), 시작하는 사람이 고름.
- 방장 전용 UI(`_isHost`)를 모두 없앱니다.

### 패널티킥
**엔진 (`penalty-engine.js`)**
- `DIRECTIONS = 3`(0 왼쪽, 1 가운데, 2 오른쪽). 같으면 선방. 5킥씩 + 서든데스 최대 5쌍 규칙은 그대로.
- `initPenaltyGame(p1, p2, { random })`: 첫 킥커 무작위. `gameId`, `series` 추가. `turnDeadline`(20초).
- 서버 타이머: 만료 시 아직 안 낸 사람의 선택을 무작위로 채워 라운드를 판정. 연속 3회 자동 선택이면 AFK가 기권 처리합니다(기존 어댑터).
- 선택 검증 범위를 `0~2`로 바꿉니다(`socket.js`의 `0~8` 제거).
- 공개 정보: `rounds`(지난 킥의 방향·결과)는 전부 공개. 진행 중 `submissions`는 기존처럼 "냈는지 여부"만.
- 옛 형식 상태(`choice > 2` 기록이 있는 판)는 복원 때 정리합니다.

**화면 (`games/penalty/`)**
- 낮 경기장: 하늘, 먼 관중석(파스텔 점), 밝은 잔디 줄무늬. 골대는 큼직하게, 3개의 터치 영역과 아래 큰 버튼 3개(왼쪽/가운데/오른쪽).
- 마스코트: 둥근 몸 + 유니폼(나=민트, 상대=분홍) + **얼굴은 프로필 이모지**. 키퍼는 장갑, 키커는 걷기 → 킥 모션.
- 상단: 점수판(●○ 5개씩), 지난 킥 방향 기록(최근 5번, 상대 것), 남은 시간 링.
- 조작: 영역/버튼 탭 = 선택(하이라이트), 큰 "슛!"/"막기!" 버튼 = 확정.
- 연출: 공 비행 0.9초 + 키퍼 다이브 + 그물 출렁 + 관중 환호/탄식 + 색종이 또는 "나이스!". 탭으로 건너뛰기 가능.
- 첫 판 요약 오버레이(3줄 이내) + 상단 `?` 버튼. `shared_preferences`의 `penalty_tutorial_seen`.
- 결과: `GameResultSheet`(무승부 포함, 전적, 재대결).

### 로비 설명 갱신 (`arcade_screen.dart`)
- 블랙잭: "숨은 카드 한 장으로 겨루는 1:1 21점 대결".
- 패널티킥: "세 칸 중 하나를 골라 골을 넣고 막아요. 먼저 5번씩 차요".

- 제로: "숫자를 숨기고 합계를 맞혀요. 5라운드 승부".

## Testing Decisions

**좋은 테스트**: 구현이 아니라 규칙과 사용자가 보는 결과를 확인합니다. 엔진은 시드/`random` 주입으로 결정적으로 돌립니다.

- **엔진(`node --test`, TDD)**
  - 블랙잭: 업카드·히트 공개 투영, 블랙잭 비공개, 버스트 즉시 종료, 선후공(패배자 후공), 2승 종료·5라운드 상한·무승부, 양쪽 준비 후 다음 라운드, 타이머 자동 스탠드, 시리즈 이어받기.
  - 도둑잡기: `drawn` 이벤트가 사용자별로 올바른 카드만 담음(상대 손패 실제 id 미포함), `discards`/`log`, 마지막 조커 판정, 결과 저장 `gameId`.
  - 제로: `resolveZeroRound` 표(정확/근접/동거리/둘 다 정확), 범위 검증, 5라운드 합산, 서든데스.
  - 해적: 선공 무작위(주입), `riskPct`, 폭발 후 상태 보존, 벌칙 검증(길이·권한·1회).
  - 패널티킥: 3방향 판정, 서든데스, 타이머 자동 선택, 옛 형식 정리.
- **균형 테스트**(시뮬레이션, 목표 범위 안인지 확인): 블랙잭 최종 무승부 < 3%, 제로 라운드 점수 갈림 > 65%이고 한 판 평균 ≤ 7라운드, 패널티킥 선방률 30~36%·무승부 < 3%. 무작위 시드 고정.
- **소켓 회귀(`socket-game-regression.test.js` 확장)**: 5종 재시작 요청/수락/거절, `gameId` 한 번만 기록, `game:reaction` 허용 목록·쿨다운, 복원, 잠수 기권.
- **Flutter**
  - 위젯 테스트: 카드 위젯(앞/뒤/조커, 글리프 없이 그려짐), 각 화면의 주요 상태(내 차례/상대 차례/결과), 제로 칩 범위, 패널티킥 3영역 탭, 해적 벌칙 입력 검증.
  - 합성음 테스트: 모든 레시피가 무음이 아니고 클리핑되지 않으며 결정적(`tank_engine_ui_test.dart`와 같은 방식).
  - 탱크 회귀: 공용 합성기로 옮긴 뒤에도 탱크 테스트가 통과.
- **스크린샷**: 로컬에서 `GAME_SHOTS=1`일 때만 생성하는 테스트(`TANK_SHOTS` 방식). 커밋하지 않습니다.
- **실플레이**: 테스트 계정 두 개로 게임마다 한 판 이상(승, 패, 재대결, 도중 나가기 포함). 결과를 PR에 첨부합니다.
