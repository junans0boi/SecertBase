# Secret Base 전체 프론트엔드 디자인 개편 설계

## 문서 상태

- 상태: 제안 완료, 구현 전 검토 대기
- 작성일: 2026-09-14
- 대상 앱: `apps/secret_base_app`
- 기준: Flutter 모바일 우선, 웹/좁은 화면 대응 포함

## 배경과 문제 정의

Secret Base는 커플의 하루를 기록하고, 관계를 이해하고, 가볍게 함께 노는 앱이다. 현재 화면은 기능이 이미 많지만 다음 문제가 반복된다.

1. 화면 대부분이 같은 흰색 카드와 텍스트 블록으로 구성되어 중요한 정보와 부가 정보의 차이가 약하다.
2. 홈과 놀이 화면은 가로 목록이 더 있다는 사실이 명확하지 않아 첫 화면에서 기능이 잘리지 않고 있다는 확신을 주지 못한다.
3. MomentLoop와 일부 빈 상태는 큰 빈 공간에 안내 문장만 있어, 사용자가 무엇을 눌러야 하는지 한 번 더 해석해야 한다.
4. 지도는 운영 환경에서 `API KEY REQUIRED`가 반복 표시되어 제품 신뢰를 훼손한다. 이는 시각 개선보다 먼저 해결해야 하는 출시 차단성 문제다.
5. 관계 이해 허브는 개인·커플·검사·사주·타로·마음관리 카드가 모두 같은 밀도로 쌓여 목적과 다음 행동이 흐려진다.
6. 운세 화면은 상단·하단 결과의 의미, 오늘의 기준, 읽는 순서가 즉시 설명되지 않는다.
7. 타로는 사용자가 22장 중 한 장을 고르는 경험이 핵심인데, 카드가 한 덩어리로 겹쳐 보이면 어떤 카드를 선택하는지와 현재 위치를 알기 어렵다.
8. 메인 탭의 각 화면이 개별적으로는 동작해도, 제목·섹션·버튼·빈 상태·오류 상태의 규칙이 통일되어 있지 않다.

이번 개편은 기능을 추가하는 프로젝트가 아니라, 이미 있는 도메인과 API를 사용자가 더 빠르게 이해하고 행동하도록 정보 구조와 시각 계층을 정리하는 프로젝트다.

## 설계 목표

- 앱을 열었을 때 `오늘 우리에게 필요한 한 가지`가 먼저 보이게 한다.
- 모든 주요 화면에 명확한 제목, 한 줄 설명, 주 행동 하나를 둔다.
- 카드 수를 무조건 늘리지 않고, 기존 `MainCard`, `CozyPage`, `mainTitle`, `mainBody`를 재사용한다.
- 상태가 없는 경우에도 안내 문장, 이유, 다음 행동을 한 덩어리로 제공한다.
- 개인 결과와 커플 결과를 화면 구조에서 분명히 구분한다.
- 운세·사주·타로는 자기성찰 콘텐츠라는 맥락, 기준 날짜, 콘텐츠 버전 또는 입력 범위를 읽을 수 있게 한다.
- 타로는 22장 카탈로그를 좁은 화면에서도 한 장씩 선택할 수 있는 캐러셀로 제공한다.
- 지도 운영 화면에서 지도 공급자 설정 오류가 사용자에게 반복 노출되지 않도록 설정을 검증하고 명확한 대체 상태를 제공한다.
- 390×844와 440×880 기준으로 세로 스크롤, 가로 목록, 키보드/스크린 리더 탐색을 검증한다.

## 범위 밖

- 새로운 운세 알고리즘, 사주 계산 규칙, 타로 카드 해석 데이터 추가
- 관계 평가 점수나 노출 권한 변경
- 상담사 마켓, 의료 진단, 자동 위기 신고, 파트너 자동 통보
- 게임 규칙과 서버 동기화 계약 변경
- 숨겨진 레거시 화면을 메인 네비게이션에 다시 노출하는 작업
- 새 UI 프레임워크, 새 상태관리 라이브러리, 새 아이콘/폰트 패키지 도입

화면에서 발견된 API 계약 문제는 기존 백엔드 계약을 유지하는 범위에서 수정한다. 계약 자체를 바꿔야 하면 별도 ADR과 별도 작업으로 분리한다.

## 사용자 경험 원칙

### 1. 한 화면에는 한 가지 주제와 한 가지 주 행동

화면 상단에서 사용자가 `무엇을 보나`, `왜 보나`, `다음에 무엇을 하나`를 순서대로 알 수 있어야 한다. 보조 기능은 하단 또는 더보기로 보낸다.

### 2. 카드가 아니라 정보의 층위를 설계한다

모든 내용을 동일한 흰색 카드로 감싸지 않는다. 다음 순서를 기본으로 한다.

- 페이지 제목과 맥락
- 오늘의 핵심 상태 또는 결과
- 주 행동
- 보조 설명과 근거
- 과거 기록·설정·전문 보기

### 3. 빈 상태도 콘텐츠다

빈 상태는 문장 하나가 아니라 `현재 상태 → 왜 비어 있는지 → 다음 행동`을 포함한다. 가능한 화면에서는 작은 일러스트 또는 기존 `CozyMascot`/아이콘을 사용하되, 장식 이미지가 행동을 가리지 않게 한다.

### 4. 가로 스크롤은 발견 가능해야 한다

가로 목록에는 첫 화면에서 일부 항목을 의도적으로 노출하거나, 좌우 그라데이션/스크롤 힌트/`더 보기`를 제공한다. 내용이 잘린 것처럼 보이지 않게 한다.

### 5. 개인·커플 범위는 시각적으로도 분리한다

탭·범위 라벨·색상은 장식이 아니라 데이터 범위를 설명해야 한다. 개인 결과를 커플 카드에 섞거나, 개인 원문을 파트너 화면에 자동 노출하지 않는다.

### 6. 전문 정보는 접어서 제공한다

사주 용어, 계산 기준, 콘텐츠 버전, 출생 입력 범위는 결과를 이해하는 데 필요한 최소 설명을 먼저 보이고 `전문 용어 보기`나 안내 영역에서 상세히 제공한다.

## 시각 방향

현재의 따뜻한 핑크/크림 팔레트와 손글씨 제목은 Secret Base의 정체성으로 유지한다. 다만 색과 카드의 사용처를 재정의한다.

### 색상과 표면

- 배경: `kMainBg`/`kBg` 계열의 매우 밝은 크림-핑크
- 기본 표면: 흰색, 정보 그룹당 한 번만 사용
- 주 강조: `kMainRose`/`kPrimary` 계열은 선택·주 행동·오늘의 상태에 제한
- 보조 강조: sage/sky/lilac/honey는 섹션 의미를 구분하는 데만 사용
- 테두리: 낮은 대비의 `kMainLine`/`kBorder`
- 그림자: 기존 낮은 그림자를 유지하되, 같은 화면에서 중첩 사용하지 않음

### 타이포그래피

- 페이지 제목: `mainTitle()`/Gaegu, 짧고 고유한 제목
- 카드 제목: Noto Sans 굵게, 한 줄 우선
- 설명: `mainBody()`/Noto Sans, 13–15px, 줄 간격 확보
- 메타·버전·날짜: muted 색상, 제목보다 작게
- 주 행동 라벨: 짧은 동사형 문장

### 컴포넌트 규칙

새 컴포넌트를 먼저 만들지 않고 현재 공통 위젯을 확장한다. 여러 화면에서 동일한 구조가 실제로 반복될 때만 공통화한다.

- `CozyPage`: 배경, 가로 여백, 기본 스크롤
- `MainCard`: 그룹 표면, 일정한 모서리/패딩
- `IconBadge`: 짧은 상태와 아이콘
- `BrandLogo`: 인증/앱 셸 공통 브랜드
- `CozyMascot`: 빈 상태의 보조 시각 요소
- `GameScaffold`/`GameMenu`: 게임 내부 공통 구조

반복되지 않는 화면 전용 래퍼, 디자인 토큰 파일, 상태관리 계층은 만들지 않는다.

## 정보 구조

### 메인 셸

기존 5개 하단 탭을 유지한다.

1. 홈: 오늘의 커플 상태와 다음 행동
2. MomentLoop: 날짜별 공동 기록
3. 지도: 장소와 추억 지도
4. 놀이: 함께할 게임과 코인
5. 더보기: 공간·기록·설정의 허브

하단 탭은 기능 추가의 장소가 아니라 반복 방문 표면이다. 세부 기능은 홈의 빠른 진입점 또는 더보기 그룹에서 열되, 메인 탭을 늘리지 않는다.

### 홈

홈은 기능 목록이 아니라 다음 순서의 오늘 화면으로 개편한다.

1. 커플 정체성 및 오늘 날짜
2. 오늘의 한 문장 또는 이어보기 상태
3. 오늘 바로 할 수 있는 주 행동
4. 주요 기능 진입점: 지도, 비밀기지, 운세, 타로, 사주
5. 관계 이해 또는 기록 이어하기
6. 최근 추억/다음 기념일 같은 보조 정보

빠른 진입점은 첫 화면에서 5개가 잘리지 않도록 2열 또는 명확한 가로 스크롤 중 하나로 정한다. 구현 시 화면 폭과 기존 접근성 테스트를 기준으로 선택한다.

### 관계 이해

허브의 첫 화면은 카드 나열이 아니라 `현재 상태 → 개인/커플 선택 → 진행 중인 항목 → 결과/기록` 구조로 바꾼다.

- 개인 탭: 나의 검사 진행, 나의 사주, 나의 타로, 개인 마음관리
- 커플 탭: 커플 검사, 궁합, 관계 사주, 관계 타로
- 상담/마음관리는 검사 결과와 같은 카드로 보이지 않게 분리
- 각 기능에는 완료/진행/정보 부족 상태를 동일한 상태 라벨로 표시

### 운세·사주·타로

운세 표면은 관계 이해 허브와 분리된 오늘 콘텐츠다. 결과를 보여주는 순서는 `오늘의 한 줄 → 좋은 흐름 → 조심할 흐름 → 힘이 되는 행동 → 기준/안내`로 한다.

사주는 `쉽게 읽기`를 기본으로 하고 전문 용어를 접는다. 타로는 `나의 타로`와 `우리의 관계 타로`를 동일한 구조로 분리하며, 선택 전과 선택 후 상태를 명확히 나눈다.

타로 선택 전에는 22장의 뒷면을 작은 카드로 배열하되 중앙 카드가 크게 보이는 수평 캐러셀을 사용한다. 현재 카드가 선택 대상임을 설명하고, 양옆 카드 탭은 중앙으로 이동시키며, 중앙 카드 탭 또는 하단 버튼만 실제 선택을 확정한다. 카드 본문은 확정 전 노출하지 않는다.

### 기록·지도·놀이

- MomentLoop: 선택한 날짜/주간 맥락, 기록 목록, 명확한 `순간 남기기` 행동
- 지도: 검색·필터·지도·장소 목록·빈 상태를 한 화면 안에서 이해할 수 있게 정리; 지도 설정 오류는 사용자용 대체 상태로 숨김
- 놀이: 코인과 출석은 상단의 보조 상태, 게임 선택은 발견 가능한 가로 목록 또는 2열 목록, 선택 전 빈 패널은 짧은 안내와 예시로 구성
- 게임 상세: 기존 규칙/동기화는 유지하고 `GameScaffold` 공통 헤더·나가기·재개 상태만 정리

### 더보기와 보조 화면

현재 더보기 화면의 그룹형 목록 구조를 기준선으로 삼는다. `내 공간`, `우리의 공간`, `기록과 이해`의 세 그룹을 유지하고, 새 기능을 메인 탭에 추가하지 않는다.

비밀기지, 상점/인벤토리, 계정/파트너, 인증, 캡슐·앨범·타임라인 등 보조 화면은 동일한 제목·설명·빈 상태·뒤로가기 규칙을 적용한다. 현재 메인 진입점에서 노출되지 않는 레거시 화면은 재설계 대상 목록에는 기록하되 구현 범위에서 제외한다.

## 상태 모델과 개인정보 경계

모든 대상 화면은 최소한 다음 상태를 설계한다.

- loading: 화면 구조를 유지하는 스켈레톤 또는 짧은 로딩 상태
- ready: 핵심 콘텐츠와 주 행동
- empty: 현재 데이터가 없는 이유와 생성/입력 행동
- error: 재시도, 뒤로가기, 지원 경로
- restricted: 개인/커플 범위 또는 출생정보 부족으로 제한된 상태

기존 API가 반환하는 범위·날짜·버전·입력 요약을 화면에 표현하되, 원문 개인정보나 위치 좌표를 새로 노출하지 않는다. 오류 문구는 내부 예외/키 이름을 그대로 출력하지 않는다.

## 품질 기준

### 기능

- 기존 API 테스트와 화면 테스트가 유지된다.
- 각 주요 화면의 주 행동이 1회 탭으로 의미 있는 다음 상태로 이동한다.
- 타로는 하루 한 장/범위별 고정 선택 계약을 유지한다.
- 개인 결과와 커플 결과의 조회 범위가 변하지 않는다.
- 빈 상태에서 사용자가 다음 행동을 찾을 수 있다.

### 접근성

- 모든 아이콘 버튼에 의미 있는 `tooltip` 또는 semantics label을 둔다.
- 주요 탭·버튼의 터치 영역은 최소 44×44 logical px을 목표로 한다.
- 색상만으로 상태를 표현하지 않는다.
- 제목과 본문 대비를 유지하고, 큰 글꼴에서 수평 잘림이 없어야 한다.
- 캐러셀의 현재 위치와 선택 방법을 스크린 리더가 읽을 수 있어야 한다.

### 시각

- 390×844, 440×880에서 핵심 콘텐츠가 화면 밖으로 잘리지 않는다.
- 가로 목록은 스크롤 가능하다는 힌트를 가진다.
- 카드·섹션·버튼의 수직 간격이 일정하다.
- 지도/이미지 공급자 오류 문자열이 일반 사용자 화면에 반복 노출되지 않는다.

### 운영

- `flutter analyze --no-pub` 통과
- 관련 단위/위젯 테스트 통과
- 프로덕션 배포 후 홈·MomentLoop·지도·놀이·더보기·관계 이해·운세·타로를 실제 화면으로 확인
- 배포 전후 health check 통과

## 단계적 출시 원칙

기능이 많은 앱이므로 한 번에 전체 화면을 바꾸지 않는다. 공통 규칙을 먼저 적용하되, 매 단계마다 독립적으로 빌드·테스트·시각 검증·배포 가능한 상태를 만든다.

1. 기준선과 공통 표면
2. 앱 셸·홈·더보기
3. 관계 이해·운세·사주·타로
4. MomentLoop·지도
5. 놀이·게임 진입
6. 비밀기지·상점·계정·인증
7. 보조 화면 정리와 전역 QA

각 단계의 상세 작업과 파일·테스트·커밋 단위는 동명의 implementation plan에 고정한다.

## 위험과 되돌리기

- 공통 토큰 변경으로 모든 화면이 흔들릴 수 있으므로 토큰 변경과 화면 변경을 같은 작은 커밋에 묶고, 각 단계의 스크린샷을 비교한다.
- 지도 설정이 배포 환경 변수에 의존하면 UI만 바꿔도 문제가 남을 수 있다. 지도 단계에서 설정 경로를 먼저 확인하고, 미설정 환경에서는 명시적 빈 상태로 안전하게 대체한다.
- 타로 캐러셀은 선택 계약과 충돌할 수 있다. 선택 확정은 중앙 카드 또는 명시적 버튼에서만 발생하도록 테스트한다.
- 큰 화면에서 잘 보이는 카드가 좁은 화면에서 넘칠 수 있다. 각 단계마다 390px 골든 또는 위젯 검증을 추가한다.
- 기존 사용자가 익숙한 메인 탭을 잃지 않도록 하단 탭 수와 순서는 유지한다.

## 완료 정의

이 설계는 다음을 만족할 때 구현 완료로 본다.

- 계획서에 명시한 노출 화면의 목적·주 행동·빈/오류 상태가 모두 문서화되고 구현됐다.
- 기존 ADR과 개인정보 경계가 유지된다.
- 시각 QA에서 반복 카드, 잘린 가로 목록, 의미 없는 빈 공간, 내부 설정 오류 노출이 해결됐다.
- 실제 프로덕션에서 주요 흐름을 새 사용자가 설명 없이 수행할 수 있다.
- 분석·테스트·배포·health check 결과가 기록됐다.
