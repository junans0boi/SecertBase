# 사주와 타로는 독립 페이지와 별도 결과 범위를 가진다

이 ADR은 ADR 0007의 운세 입력 허용 범위와 `사주 형식` 콘텐츠 표현에 관한
이전 결정을 대체한다. ADR 0007의 저장 범위·provider fallback·상담 격리 결정은
그대로 유지한다.

Secret Base의 운세 표면은 홈에서 진입하되, 사주와 타로를 서로 다른 페이지로
제공한다. 사주 페이지에는 먼저 `나의 사주`, 이어서 활성 Couple이 있을 때
`우리의 관계 사주`를 보여준다. 타로 페이지도 `나의 타로`와 `우리의 관계 타로`를
같은 순서로 보여준다.

## 사주 계산과 입력

사용자가 제공한 [사주120일의 도전 참고 PDF](../product/reference/saju/23-saju-120-day-challenge.pdf)를
사주 용어와 계산 규칙의 참고 기준으로 삼는다. v1은 출생년월일시에서 년주·월주·일주·시주를 계산하고, 년주는 입춘,
월주는 24절기의 입절 경계를 사용한다. 시주는 문서에 적힌 한국 표준시 135도,
00:30 기준의 조자시·야자시 구분, 경계 시각과 역사적 서머타임 보정 규칙을
계산 정책 버전으로 기록한다. 다른 국가·시간대의 보정은 같은 정책을 명시하기
전까지 완전한 명식으로 가장하지 않는다.

출생 프로필의 생년월일과 달력 유형, 시간대는 필수다. 출생 시각 또는 출생지가
없으면 시주·현지 시간 보정이 확정되지 않으므로 완전한 사주팔자 결과를 제공하지
않는다. 사용자가 `제한된 정보로 보기`를 선택한 경우 알려진 기둥만 계산하고,
누락된 기둥과 해석 범위를 결과에 표시한다. 없는 시각이나 장소를 기본값으로
채우지 않는다. 생년월일·달력 유형·시간대가 없으면 계산을 시작하지 않고
`출생정보 수정하기`로 보낸다.

사주 결과는 `쉽게 읽기`와 `전문 용어 보기`의 두 표현 층을 제공한다. 전문 층에는
사주팔자, 천간·지지, 오행, 십신 등 실제 계산에 사용한 용어와 한자를 보여줄 수
있지만, 어느 층도 사실로 검증된 예측이나 의료·심리 진단으로 표시하지 않는다.
성별에 의존하는 전통 해석은 v1 입력으로 성별을 수집하거나 단정하지 않으며,
성별 중립적인 계산·설명 범위만 사용한다.

## 구현 상태 (2026-09-10)

개인 사주와 관계 사주 요약 첫 slice는 `k-saju@0.1.4`를 서버에 고정하고
`saju-v1-k-saju-0.1.4`를 계산 버전으로 반환한다. 한국 표준시(`Asia/Seoul`)와
1900–2050년은 완전 계산 범위로 두며, 다른 시간대는 제한 결과로 표시한다. 출생지는
사용자 입력 문자열만 결과 요약에 보존하고 좌표 변환에 사용하지 않는다. 결과는
legacy `relationship_fortune_contents`와 분리된 `relationship_saju_results`에
입력 fingerprint·모드·계산 버전과 함께 저장한다. `GET/POST /api/relationship/saju`와
Flutter `SajuScreen`은 쉬운 설명·전문 용어 보기와 누락 입력의 명시적 제한 선택을
제공하며, Couple이 있으면 점수 없이 관계 패턴과 대화 질문을 추가한다. 타로 페이지는
메이저 22장 정방향 카탈로그를 날짜와 범위에 고정해 개인·관계 카드를 하루 한 장
제공하며, 재추첨 endpoint를 제공하지 않는다. 결과는 `relationship_tarot_contents`
에 저장하고, Flutter는 `TarotScreen`에서 개인·관계 카드를 분리해 보여준다.

## 타로와 저장 범위

타로는 카드 카탈로그 버전과 날짜를 기준으로 사용자마다 하루 한 장을 처음 뽑고,
그 결과를 개인 범위에 저장한다. 활성 Couple의 관계 타로는 Couple 범위에 하루
한 장을 저장하여 두 사람이 같은 카드를 본다. 같은 날짜에는 다시 뽑기와 스프레드를
제공하지 않는다. 출생 프로필은 타로 카드 선택에 필수가 아니다.

개인 결과는 사용자의 저장된 IANA 시간대 기준 날짜를 사용하고, 관계 결과는 API가
반환하는 저장된 `contentDate`를 함께 표시한다. 사주와 타로 모두 모드, 범위,
계산·해석 기준, 콘텐츠 버전, 사용한 입력 정보의 요약을 반환한다.

## Consequences

- 사주와 타로의 목적과 입력 계약이 섞이지 않는다.
- 실제 사주 계산 결과와 사용자가 읽기 쉬운 설명을 같은 결과의 두 표현으로 유지한다.
- 누락된 출생 정보를 조용히 추정하지 않아 계산 경계가 사용자에게 보인다.
- 커플 타로·사주 결과는 Couple 범위를 따르며, 개인 원문이나 개인 명식을 파트너에게 자동 공개하지 않는다.
- 남은 구현은 마음관리·안전 리소스와 변화 비교이며, 사주·관계 사주·타로는
  입춘·자시·음력 윤달·지원 범위 및 날짜 고정 fixture와 인증 REST/Flutter 테스트로
  검증한다.
