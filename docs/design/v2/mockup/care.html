무엇이 달라지나요

  • 안전 안내를 앱 안에 내장 — 112·119·109 등 핵심 연락처를 앱에 고정해 두어, 서버 리소스 API가 실패하거나 오프라인이어도 바로 보여요. 연락처 줄은 탭하면 전화 걸기/번호 복사가 돼요. (분석 문제 1·2)
  • ‘도움이 필요하면’ 칩 상시 노출 — 우리 이해 홈·돌봄·상담·마음관리 상단에 항상 있고, 누르면 위기 시트가 열려요.
  • 위기 순간에는 먼저 안내, 위치는 나중에 — 지금은 ‘안전하지 않아요’를 누르는 순간 위치 권한을 요청해요. 2.0은 일반 안내와 연락처를 먼저 보여 주고, 위치는 설정의 사전 선택 토글이나 안내 카드의 ‘위치로 찾기’를 눌렀을 때만 써요. (문제 2)
  • 입장 시 동의 시트 1회 — AI 가이드·의료/전문 상담 아님·비공유·AI 서비스 전송·위급 시 연락처를 한 장에 담아요. 허브 카피 ‘상담사와 채팅하듯’은 삭제. (문제 5)
  • 서버 safety 연결 — 상담 위기 응답의 ‘아래 도움 기관을 확인해 주세요’가 앱에서 끊기던 문제를 연락처 카드로 이어요. LLM이 꺼져 있을 때는 같은 문장 반복 대신 ‘기본 안내’ 배지와 호흡·휴식 안내를 보여요.
  • 마음관리는 차분한 다크 라일락 — 고정 선택지 채팅이라 쓰지 않고 눌러서 답해요. 안전 확인 선택지는 모두 같은 무게로 보여요(‘안전하지 않아요’만 눈에 띄게 하지 않음).

  • 안전·동의: 동의 시트 · 돌봄 홈(상시 칩+핵심 번호 버튼) · 위기 시트 · 위기 시트(오프라인) · 전화/복사 · 돌봄 설정(위치 사전 선택·기록 삭제·확인일)
  • 마음관리(다크): 시작 · 진행 · 안전 확인 · 안전 응답(연락처+선택형 위치) · 완료 · 오류(선택 저장됨)
  • 상담: 빈 상태 · 대화 · 입력 중(멈추기) · 전송 실패(다시 보내기/삭제) · 위기 응답+연락처 카드 · LLM 대체 문구(기본 안내) · 공유 힌트 승인
  • 연락처 5곳(112·119·109·1577-0199·1366)의 번호·명칭·운영 시간은 확인 필요(검수)예요. 목업의 ‘마지막 확인 2026년 10월’은 예시 값이에요.
  • 톤은 담담하고 약속하지 않아요(‘괜찮아질 거예요’ 같은 보장 문구 없음).

승인받고 싶은 결정

  • 상담을 마음관리 안으로 통합할까요? 통합하면 동의·안전 확인·위기 응답이 한 흐름이 되고 입구가 하나가 돼요. 목업은 우선 두 입구를 나란히 두고 같은 안전 장치를 공유해요.
  • 위치는 기본 꺼짐으로 시작해도 될까요? 꺼져 있어도 112·119·109는 항상 보여요. 켜 두면 위기 때 가까운 기관이 함께 나와요.
  • 상담에서 서윤에게 힌트를 보내는 기능을 1.0에 포함할까요? 보낼 때마다 한 문장 단위로 승인받는 방식이에요.

구현 때 필요한 서버·정책 작업

  • 서버 safety 필드·resources(srv/routes.js:8060-8095 부근)를 앱 counseling_api/화면에 연결, 마음관리의 위치 요청 제거.
  • 위기 연락처 번호·명칭·운영 시간 검수(담당자 지정)와 validUntil(2027-12-31) 갱신 담당·알림 체계. 앱 내장본과 서버본 불일치 시 우선순위. 확인 필요(검수)
  • 외부 LLM으로 입력 텍스트가 전송되는지 확정하고, 약관·개인정보 처리방침·동의 시트 문구를 일치시키기. 법무 확인 필요
  • 동의 이력 저장(동의 버전·시각)과 동의 철회/기록 삭제 API, 비공유 보장(상대에게 노출 경로 없음) 점검.
  • LLM_PROVIDER 비활성 시 기본 안내 문구를 여러 개로 로테이션하고 ‘기본 안내’ 상태를 응답에 표시.
  • 오프라인 시 위기 시트는 번들 연락처만 사용, 지역 정보는 연결 후 보강(위치 사용 시 서버에 저장하지 않음).
