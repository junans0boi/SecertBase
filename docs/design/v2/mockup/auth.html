시작 · 인증

무엇이 달라지나요

  • 브랜드 단일화 — 인증 화면만 네이비 auth* 8색·입력 반경 18을 쓰고 다음 화면은 장미+손글씨체라 가입 직후 인상이 바뀌었어요(§3-1). 모두 장미 그라데이션 + 하트 열쇠구멍 문 엠블럼 + 공용 컴포넌트로 통일해요.
  • 온보딩 3장 — 동작 없는 장식 점 3개(§3-13)를 진짜 3장 온보딩으로 바꿔요. 건너뛰기 가능, 마지막 장에서 “시작하기”.
  • 로그인 — Google이 주 버튼, 이메일은 보조 시트. 이용약관·개인정보처리방침 링크는 항상 보여요(§3-13). 비밀번호는 trim하지 않아요. 입력 오류는 필드 아래 글자+아이콘으로, 로딩 중엔 버튼이 바뀌고 입력은 잠겨요.
  • 가입 — 1/2 이름·닉네임·생일, 2/2 이메일·비번 규칙을 입력하는 동안 인라인 검증, 전체 동의+개별 동의(만 14세·약관·개인정보 필수, 마케팅 선택). 서버 오류 코드별 문구(이미 가입된 이메일 등, §3-6), 가입 후 자동 로그인(§5).
  • Google 신규 — 지금은 약관 동의 없이 계정이 만들어지고 생일이 2000-01-01로 들어가요(§2-B, §3-2). 닉네임·생일·동의를 거쳐야 시작할 수 있어요.
  • 비밀번호 재설정(신규) — 앱·서버 모두 없던 기능(§3-4). 입력 → 발송 완료 → 오류. 가입 여부를 드러내지 않는 같은 안내문.
  • 연결 로딩·실패·오프라인 — 개발용 “v1.0.4 - 상태” 문구 제거(§3-11). 실패·오프라인에서도 재시도와 로그아웃이 보여요. 점검·강제 업데이트는 P2로 함께 그려 뒀어요.

승인받고 싶은 결정

  • Google 가입 때 생일을 필수로 받을까요? 필수면 사주·운세가 정확해지지만 가입 단계가 하나 늘어요. 선택으로 두면 나중에 “운세” 첫 진입 때 묻는 방식도 가능해요. (목업은 필수안)
  • 비밀번호 규칙은 8자 이상 + 영문·숫자 포함으로 할까요? (지금은 변경할 때만 6자 검사)
  • 마케팅 알림 수신 동의를 가입에서 선택 항목으로 받을까요, 아예 빼고 1.0은 서비스 알림만 보낼까요?

구현 때 필요한 서버·정책 작업

  • 비밀번호 재설정 API(요청·토큰 메일 발송·재설정 완료), 메일 발송 수단, 재전송 쿨다운(예: 60초), 링크 유효시간(1시간 제안), 앱 딥링크.
  • 동의 이력 필드(약관·개인정보·만 14세·마케팅의 동의 시각·버전). Google 신규 가입에도 같은 동의 저장. 현재는 서버에 이력 필드가 없어요.
  • 만 14세 미만 가입 차단 정책: 생일로 서버에서도 검증, 거절 문구 확정. register()가 bool만 돌려줘 email_already_exists·invalid_birth_date가 사라지는 문제 수정(§3-6).
  • Google 신규에서 BirthDate '2000-01-01' 삽입(routes.js:471-475) 제거 + 미입력 계정의 보정 시점.
  • 콜드 스타트: 로컬 세션으로 먼저 runApp, 프로필 재조회는 백그라운드(§3-5). 점검·강제 업데이트는 서버가 최소 버전·점검 플래그를 내려줘야 해요(현재 지원 여부 확인 필요).
  • Google 로그인 버튼은 Google 공식 브랜드 가이드의 에셋을 써야 해요(목업의 G는 대체 표시).
