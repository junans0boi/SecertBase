  • 장소 추가는 미니 시트 하나예요. 이름·카테고리를 미리 채우고 “가고 싶어요 / 다녀왔어요” 두 버튼으로 끝. 좌표는 숨기고, 지도에서 직접 고르면 이름이 필수예요. (M6)
  • 장소 상세는 요약 · 우리 이야기 · 더보기 3섹션 + 하단 고정 CTA(길찾기 / 다녀왔어요·순간 남기기). 가짜 하트·댓글·리뷰를 없애고 “둘의 한마디”와 연결된 추억으로 바꿔요. (M7, S5)
  • “다녀온 뒤”를 우리의 여운으로 정리했어요. 방문 전 / 나만 / 둘 다 / 상대 삭제 / 로드 실패를 모두 설계했고, 둘 다 남겨야 서로 열려요. (M8 “Date Afterglow” 영문 제거)
  • 연결 안 됨·서버 오류를 “빈 지도”로 오표시하던 문제를 별도 상태(미연결 / 타일·로드 오류 / 검색 없음)로 나눴어요. (S4)

화면 구성

  • 메인: 핀+칩+범례 · 빈 지도 · 위치 사전 안내 · 위치 거부 · 타일 오류 · 미연결
  • 검색: 입력(최근·저장 장소) · 결과(우리 장소/새 장소) · 없음
  • 추가: 미니 시트 · 이름 필수 · 저장 중
  • 상세: 요약 · 우리 이야기(추억 유/무) · 더보기 · 공유 카드
  • 여운: 방문 전 · 아직 안 남김 · 나만 · 둘 다 · 상대 삭제 · 로드 실패, 남기기 시트(기본 / 후보 없음 / 저장 중 / 성공 / 실패)
  • 목록 시트: 전체 · 정렬 · 빈 결과

승인받고 싶은 결정

  • 지도 타일 제공자: OSM 공용 서버를 계속 쓸까요, 상용 타일(계약형)로 바꿀까요? 출시 후 트래픽이 정책 한도를 넘을 수 있어요.
  • 여운 공개 규칙: 시안처럼 “둘 다 남겨야 서로 열림”으로 갈까요, 상대 것은 바로 보이게 할까요?
  • 장소 저장 두 버튼 중 어느 쪽을 기본(진한 색)으로 할까요? 시안은 “가고 싶어요”가 기본이에요.

구현 때 필요한 서버·정책 작업

  • 타일 제공자 결정 및 Nominatim 폴백 제거(검색어가 제3자로 전송됨). 검색은 자체 프록시 또는 계약형 API로. 개인정보처리방침에 “검색어 처리” 반영.
  • 409 active_couple_required / ok:false 응답을 미연결·오류 상태로 매핑. 위치 요청은 사용자 행동 시점으로 이동하고 탭 전환 시 지도 상태 보존.
  • “한마디”(1인 1개, 40자), “여운”(감정 태그·메모·연결 기록 id, 상대 삭제 알림) 스키마와 PATCH /map/:id 작성자 제한 확인(확인 필요).
  • 사전 안내 시트의 “위치를 공유하지 않아요” 문구는 safety_location 권한 문구와 충돌하지 않는지 확인(확인 필요). Android·iOS 위치 권한 문구 정리.
