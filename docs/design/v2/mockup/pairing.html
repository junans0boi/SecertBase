2.0 제안

파트너 연결 · 권한

무엇이 달라지나요

  • 3단 스텝(공유 → 입력 → 축하) — 지금은 한 화면에 6블록(내 코드, 상대 코드, 상태, 받은/보낸 요청, 보관함, 닉네임)이 몰려 위계가 없고(§3-12), 코드를 복사해 수동으로 전달해요. 스텝 표시로 지금 어디인지 보이게 하고 각 화면의 주 행동은 하나로 줄여요.
  • 공유 시트·딥링크 — 초대 문구 미리보기와 링크로 연결: 상대가 링크를 누르면 코드가 자동 입력돼요. 3초 폴링 대신 수락 푸시로 알려요(§3-12).
  • 입력 오류·만료·이미 연결됨을 각각 다른 말로 안내하고 코드 붙여넣기를 돕는 칩을 둬요.
  • 연결 축하 + 첫 사용 체크리스트 3개(시작일·첫 순간·알림)로 빈 홈에 떨어지지 않게 해요.
  • 권한은 쓰는 순간에 — 푸시는 축하 화면 직후 사전 안내 시트 → OS 요청, 거부하면 설정 이동 배너. 위치는 지도 진입 즉시가 아니라 “내 위치”를 누를 때 용도 시트 후 요청(§3-7). 거부 후에도 지도 검색은 쓸 수 있어요.
  • 연결 전에도 접근되는 메뉴 — 오버플로(⋮)에 고객센터·약관·개인정보처리방침·로그아웃·회원 탈퇴. 지금은 로그아웃뿐이라 연결 전 사용자는 앱 안에서 탈퇴할 수 없어요(§3-3, Play 계정 삭제 요건).
  • 개인 보관함 카드 — 맨 아래 설명 없는 버튼을 기록 있음/없음 카드로 승격하고 연결 후 안내를 붙여요. 탈퇴는 경고 → 확인 입력 → 완료 3단.

승인받고 싶은 결정

  • 연결 전에 앱을 둘러볼 수 있게 할까요? 허용하면 첫인상은 좋아지지만 홈·기록·지도 전부에 “미연결” 상태를 만들어야 해요. 지금 목업은 연결 전엔 이 화면 + 개인 보관함만 쓰는 안이에요.
  • 연결하면 개인 보관함 기록은 어떻게 할까요? 지금은 연결되면 보관함 접근이 막혀요(서버 409). 목업은 “잠기고 내보내기만 가능” 문구인데, “우리 기록으로 옮기기”도 가능한지 정해 주세요.
  • 탈퇴 때 연결된 상대에게 남는 것: 상대 화면에서 내 기록·사진을 지울지, 남길지(내 이름만 익명 처리) 정해야 탈퇴 경고 문구를 확정할 수 있어요.

구현 때 필요한 서버·정책 작업

  • 초대 링크·딥링크(앱 링크/유니버설 링크, 미설치 시 스토어 → 설치 후 코드 이어받기) 도메인과 연결 코드 유효시간(24시간 제안) 및 만료 응답 코드. 자기 코드 입력·이미 연결된 코드·없는 코드의 서버 오류 코드 구분.
  • 연결 요청 수락/거절 푸시, 3초 폴링 제거(§3-12). 닉네임 수정이 생일을 2000-01-01로 덮어쓰는 버그 수정.
  • 푸시·위치 사전 안내는 앱 기능이지만, 위치 문구(“저장하거나 공유하지 않아요”)는 실제 처리 방식과 개인정보처리방침이 일치하는지 확인 필요. 매니페스트의 CAMERA/RECORD_AUDIO 사용 여부(§3-20).
  • 회원 탈퇴: 연결 전 사용자도 호출 가능한 API(+ 비밀번호 재확인, Google은 재인증 방식 확정), 탈퇴 후 데이터 삭제 범위·보관 기간, 연결 상대 처리. 탈퇴 실패 시 ($error) 노출 제거(§3-11).
  • 설정 화면이 ApiClient 대신 http를 직접 부르는 문제(§3-14)는 이 흐름에도 적용해 401·타임아웃 처리를 통일.
