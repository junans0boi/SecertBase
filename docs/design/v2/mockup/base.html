비밀기지 · 기념일 · 엽서 · 추억

흩어져 있던 네 화면(보상 목록, 기념일, 월간 엽서, "n년 전 오늘")을 비밀기지 한 곳의 탭 4개(보상 · 기념일 · 엽서 · 추억)로 묶었어요. 홈 바로가기 "비밀기지"와 더보기 > 우리 이야기에서 들어와요.

무엇이 달라지나요

  • 보상이 "목록"에서 "진행"으로 바뀌어요. 상단에 진행바 "8/21"과 받을 보상 개수를 두고, 받을 수 있는 보상을 가장 위에 모아요. 전에는 21개가 고정 순서로 나열돼 어디까지 왔는지 몰랐어요(분석 #11).
  • 그룹 3개(순간 · 장소 · 함께한 날)로 나누고, 진행 중인 항목엔 "41/50" 같은 진행도를 보여요. 등급(B~SSS)은 "등급이 뭐예요?" 시트로 설명하고, 흐릿한 투명도 대신 읽히는 색을 써요(#8).
  • 보상을 받으면 연출 모달이 뜨고, "놀이에서 써 보기"와 "꾸러미에서 보기"(상점)로 이어져요. 받기만 하고 끝나던 흐름을 닫아 줘요.
  • 기념일에 시작일 편집과 자동 마일스톤(100일·200일·1주년…)이 합쳐져요. 다가오는 순으로 정렬하고, 비반복 기념일도 D-day를 보여요. 삭제는 스와이프 + 실행 취소로, 날짜는 한국식 표기(2027.2.2 화)로 바꿨어요(#10).
  • 엽서는 엽서 모양 카드예요. 이미지 저장·공유가 생겼고, 달을 넘길 때 이전 엽서를 흐리게 유지해서 깜빡이지 않아요(#14).
  • 추억 항목은 눌러서 해당 기록으로 가요. 해가 쌓이면 연도별로 묶이고 당겨서 새로고침해요(#13). 화면에 새어 나오던 내부 용어를 모두 없애고 해요체로 통일했어요(#12).
  • 데이트 룰렛(P2)은 "오늘 뭐 할까요?"로 이름을 바꾸고, 결과를 지도 "가고 싶은 곳"이나 기념일로 보낼 수 있게 했어요(#15).

승인받고 싶은 결정

  • 네 화면을 탭 4개로 묶는 구성이 괜찮을까요? 대안은 "보상"만 허브로 두고 기념일·엽서·추억은 더보기와 홈에서 각각 들어가는 방식이에요.
  • 시작일을 바꾸면 이미 받은 보상은 그대로 두고, 아직 못 받은 날짜 보상만 다시 계산할까요? (시트에 그렇게 안내했어요)
  • 룰렛의 진입점은 어디가 좋을까요? 후보: ① 지도 탭 상단 "오늘 뭐 할까요?" ② 홈 바로가기 4번째 칸 교체 ③ 놀이 탭. (홈은 4칸을 지키고 싶어서 ①을 추천해요)

구현 때 필요한 서버·정책 작업

  • 마일스톤 진행도 value 채우기: 지금 서버가 value를 안 보내서 "41/50"을 그릴 수 없어요(routes.js:3834). 순간·장소·방문 개수를 value/target으로 내려 주세요. 날짜 마일스톤은 D+n과 남은 일수를 앱이 계산해요.
  • 기준일 통일: 마일스톤은 COALESCE(StartDate, ActivatedAt)라 홈 D-day와 다를 수 있어요. 둘 다 같은 StartDate를 쓰도록 맞추고, 시작일 변경 시 미수령 날짜 보상만 재계산해요.
  • 기념일 API: 자동 마일스톤(100/200/365/500/730…)을 기념일 목록 응답에 합쳐 내려 주고(읽기 전용, "자동" 뱃지), 비반복 기념일도 days_left를 계산해요(routes.js:5676, 5759). 삭제 실행 취소는 삭제를 지연 커밋(5초)하거나 복구 API를 둬요.
  • 엽서: 이미지 렌더(앱에서 캡처)와 월 1일 푸시는 정책 확인이 필요해요. 엽서 응답에 대표 장면 썸네일과 방문 수를 추가해요. 월간 푸시가 이미 있는지는 확인 필요예요.
  • 추억: 항목 탭 → 기록 상세 이동용 post id와 years_ago(이미 내려오고 있어요)를 그대로 쓰고, 목록 API에 새로고침(재조회)만 연결해요.
  • 룰렛: 지도 "가고 싶은 곳"(위시리스트) 저장 API가 지도 영역에서 먼저 필요해요. 아이디어 20개는 앱 내장 목록을 그대로 쓰고 카테고리·소요시간 태그만 붙여요.
  • 보상 수령 후 놀이·상점 딥링크(예: secretbase://play, secretbase://shop/inventory)를 정의해요.
