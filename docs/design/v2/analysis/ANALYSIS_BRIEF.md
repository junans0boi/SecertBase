# 비밀기지(Secret Base) 2.0 분석 브리프 (게임 탭 제외 전 기능)

배경: 커플용 앱 "비밀기지". 게임 탭(모든 게임)은 이미 2.0 디자인이 끝났다. 이제 **게임 탭을 제외한 모든 기능**(로그인·온보딩, 홈, MomentLoop, 비밀지도, 타로, 사주, 궁합, 상담, 마음케어, 기념일, 상점 등)의 2.0을 만든다. 목표: 곧 있을 정식 출시(Play)를 위한 **완전하고 사용하기 편한 UI/UX**. 지금 디자인도 나쁘진 않지만 더 정리·개선한다. 이 분석은 2.0 기획과 HTML 목업의 근거 자료다.

규칙: **레포 코드를 수정하지 말 것(읽기 전용)**. 산출물은 마크다운 파일 하나만 아래 지정 경로에 쓴다. 코드는 `/Volumes/WorkSpace/Project/SecertBase/.claude/worktrees/games-v2-r4-settings/` 아래 읽기(앱 `apps/secret_base_app/lib/`, 서버 `services/realtime-server/src/`, 제품 문서 `docs/` — 특히 `docs/PRODUCT_SPEC.md`, `FEATURE_MATRIX.md`, `MVP_DEFINITION.md`, `ROADMAP.md`, `MOMENTLOOP_PLAN.md`, `SECRET_MAP_PLAN.md`, `RETENTION_FEATURE_PLAN.md`, `docs/product/`). 공용 디자인 토큰은 `lib/core/app_theme.dart`, `lib/core/main_design.dart`, `lib/ui/`, `lib/widgets/`. 화면 이동 구조는 `lib/screens/home_shell.dart`, `lib/main.dart`, 각 화면의 `Navigator.push`/라우트 호출을 따라가며 확인한다.

산출물 구조(한국어, 구체적으로, 코드 근거는 `파일:줄`로):
1. **화면·기능 인벤토리**: 화면별 한 줄 목적, 핵심 요소(위젯·버튼·입력), 진입 경로, 관련 서버 데이터. 표 형식 권장.
2. **주요 사용 흐름** 3~6개(첫 사용·일상·재방문 관점) — 현재 몇 번 탭으로 가는지 포함.
3. **UX/UI 문제점**: 심각도(상/중/하), 근거(파일:줄 또는 화면 설명), 영향. 정보 위계·내비게이션 깊이·빈 상태·로딩/오류 처리·접근성(터치 영역·대비·글자 크기)·카피(톤·문구)·일관성(색·간격·컴포넌트 중복)·출시 준비도(설명 부족, 권한 요청 타이밍 등)를 본다.
4. **2.0 개선 제안**: 정보 구조(무엇을 합치고/나누고/숨길지), 화면별 개선 방향, 빠진 화면(빈 상태, 온보딩, 오류, 권한 안내, 설정 연결 등), 재사용 컴포넌트 후보.
5. **2.0 목업 대상 화면 목록**: 우선순위(P0 출시 필수 / P1 중요 / P2 선택)와 화면별로 목업에서 보여야 할 상태(예: 기본, 빈 상태, 로딩, 오류, 입력 중).
길이: 1,500~2,500단어. 군더더기 없이. 확신 못 하는 것은 "확인 필요"로 표시.
